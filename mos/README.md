## Princípio central

> Se uma tarefa precisa ser executada duas vezes, ela deve ser documentada.
> Se precisa ser executada muitas vezes, deve ser padronizada.
> Se for repetitiva, deve ser automatizada.

## Como atualizar o manual

1. Cada alteração relevante é registada no `17-changelog.md`.
2. Capítulos mudam de versão (ex: `1.1`, `1.2`) a cada revisão.
3. Nenhuma alteração é feita diretamente no Git sem registo no changelog.
4. O manual é parte da entrega — se uma tarefa nova for executada duas vezes, é documentada aqui.
